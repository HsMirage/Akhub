## 本轮发现并修复的问题

1. **（严重）宽限期从进程启动即计时**：`serve_with_shutdown` 用
   `tokio::time::timeout(grace, serve)` 包住整个服务，导致线上每 180 秒
   自行退出一次（部署后观察到 `NRestarts=21`，管理会话反复丢失）。
   修复为"先等停止信号，再开始计宽限期"，并在 `tests/release_harden.rs`
   增加回归测试（无信号时超过数倍宽限期不得退出）。
2. **Sub2API 探针现场字段形状不符**：现场返回
   `sub2api.key_billing` + `schema_version` / `billing_scope` /
   `effective_rate_multiplier` + RFC3339 `observed_at`，旧解析只认
   `billing` / `version` / `scope` / `effective_multiplier` / Unix 秒。
   已改为两代形状兼容（含现场样本单元测试），线上倍率由 unknown 变为已知。

## 上游侧观察（非 Akhub 缺陷，记录备查）

- newapi 未实现 `/v1/messages/count_tokens` 与 `GET /v1/models/{model}`；
  依赖 Claude Code 上下文管理的场景需要换成实现了该端点的上游。
- sub2api 对同一账号的并发有服务端限制，快速连打多个流式请求会返回
  `Concurrency limit exceeded for account`；Akhub 原样透传该错误，不静默重试。
- sub2api 的生图权限按分组开关，`gpt-image-2` 在本次验收中已可用（生成与编辑）。
