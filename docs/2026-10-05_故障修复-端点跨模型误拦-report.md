# 端点跨模型误拦修复

## 当前结果

代码已修复并通过本地验证，**尚未发布、尚未部署**。本次没有修改版本号、创建发布标签或切换服务器；线上仍是前一次部署的版本，不包含本次修复。

404/405 的影响限制在当前请求内，不再让一个模型的失败关闭整个账号的原生接口，也不会将共用账号或 Key 判入冷却。

## 故障依据

2026-10-04 的现场记录：22:09:06，`gpt-6.1-sol` 正常；22:10:33，同账号的 `gpt-6-luna` 返回「没有可用于本次请求的端点」；随后前者被过滤为「能力不支持」。22:12:26 的外层日志与客户提供的 503 文案一致，Akhub 记录中上游尝试次数为 0。

历史配置中该账号首选 Chat、开启运行时适配。旧代码把非首选接口的一次 404/405 记成「账号 + 接口」维度的 24 小时禁令，判断没有模型或凭据维度。同账号其他模型因此被连带拦截；无可用转换时的泛化错误还会触发账号健康状态变化。

最初上游错误正文未保留，无法还原该次 404/405 的具体业务原因。此次回归覆盖两种状态码与已经成功过的原生接口，不依赖对上游错误文案的猜测。

## 修改内容

- 删除跨请求的接口缺失缓存。保留真实成功记录，仅作为端点排序提示。
- 本次遇到非首选端点 404/405 时，仍可尝试能表达请求的其他端点。每轮最多两个不同端点，避免循环；下一次请求重新从原生端点开始。
- 404/405 不再触发共用账号或 Key 冷却。鉴权失败、额度、限流、网络及服务端故障继续走各自规则。
- 没有可用转换时保留原始状态码和经过脱敏的错误说明，不再只显示「没有可用端点」。
- 删除依赖旧缓存的概览告警字段与提示，后台 Responses 的选择也不再受历史接口拒绝影响。
- 自定义工具及原生字段保持原样；不通过删工具或强行转换让请求表面成功。

## 验证

新增 5 项 HTTP 回归测试，覆盖：

1. 一个模型被 404/405 拒绝后，同账号另一个模型仍能完整返回原生流式响应。
2. 重复六次拒绝不会冷却共用账号或 Key，覆盖首选与非首选 Responses 两种配置。
3. 本次接口转换成功后，下一次请求会恢复原生端点。
4. 转换不可行时保留真实错误；全部端点拒绝时有界结束。
5. 一个目标拒绝后仍可换到另一个目标，并保留自定义工具与流式语义。

最初四项在修改前全部失败，修复后全部通过；补充第五项验证跨账号切换。完整后端测试共 709 项通过；前端测试、前端构建、后端静态检查和差异格式检查通过。测试使用本地可编排上游，没有向线上客户请求注入故障。


## 影响与下一步

对于实际上缺少原生接口的上游，后续请求可能多一次失败尝试；这是移除跨模型误拦所需的明确取舍。已确认只支持某种协议的账号，可使用现有首选协议与运行时适配设置控制访问路径，无需新增模块。

当前等待用户决定何时发布。单个模型真的不受上游支持时仍会失败；本次修复保证它不再连累同账号其他模型。
