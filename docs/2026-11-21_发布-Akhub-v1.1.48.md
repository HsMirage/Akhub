# v1.1.48 发版记录

基线 v1.1.47。**没有结构变更**，启动不迁移数据。

## 为什么 v1.1.47 没修好

v1.1.47 补的计费终止帧排在**错误事件之后**。下游 sub2api / newapi 读到错误事件就
**停止解析后续帧**，排在后面的用量帧永远进不了它们的计费统计，于是现场表现从
"没有记录"变成了"记录在、没有错误、输入输出 0、计费 0"（请求
`req_01M7X6SW67MRXKP6KPM9Z6SAVD`，流内 cyber-policy 拒绝）。

## 发版内容

| # | 修复 | 落点 |
|---|---|---|
| 1 | 错误事件**之前**补一帧「只有 usage、没有终止信号」的用量帧：下游先记到用量，再看到错误 | `src/gateway/settle.rs`、`src/protocol/mod.rs` |
| 2 | 错误事件**之后**仍补协议终止帧（与上游 newapi 一致）：sub2api 的 raw 路径靠它清掉「非计费错误」标记 | `src/gateway/settle.rs` |
| 3 | 上游报 0 输入等于没报：退回请求体估算（跨协议转换的开场占位常带 `input_tokens:0`，否则下游照旧按 0 计费） | `src/gateway/stream.rs` |
| 4 | akhub 记录页在异常结束且上游没报量时，显示**下发给下游计费的那一份**估算，不再永远是「未知 / 未知」 | `src/gateway/settle.rs` |

## 顺序为什么是「用量 → 错误 → 收尾」

| 下游 | 读到错误帧 | 计费结果 |
|---|---|---|
| sub2api raw 路径 | 先累计已到达的用量，再置「非计费」标记 | 错误**之后**的收尾帧清掉标记 → 按真实用量计费 |
| sub2api compat 路径 | 直接结束解析 | 错误**之前**的用量帧已经被累计 → 用量正确（是否计费取决于它的非计费标记，见 issue #456） |
| new-api | 透传错误，继续读 | 用量帧与收尾帧都能读到 |

客户端没索取 usage 时（`strip_unrequested_usage`）不塞额外用量帧，保持原契约；
计费型下游（sub2api / newapi）都会强制打开 `include_usage`。

新增用例：

- `an_upstream_error_event_bills_usage_before_the_error_frame`：现场回归。上游流内
  cyber-policy 错误帧时，用量帧必须排在错误之前、非零输入、错误之后再补收尾帧。
- `a_fragmented_error_stream_still_emits_billing_usage_before_the_error`：上游按 1
  字节一块分片时，按帧边界切块转发仍不丢字节、顺序不乱。
- `usage_only_frame_has_no_terminal_signal`：三个协议的用量帧形状都不带终止信号。
- `billing_usage_*`：缓存并入输入、上游报 0 时退回估算。

## 已知取舍

- sub2api 的 **compat 路径**（inbound Chat + upstream Responses 的桥）读到错误事件后
  直接结束解析并把整条请求标记为非计费，所以即使拿到用量也可能记 0 费用。这属于
  sub2api 的计费策略，已提 issue：https://github.com/kiss-kedaya/sub2api/issues/456
- 客户端真断开（`client_gone`）时连接已没，补帧送不到下游；记录页保持「上游没报
  就不写」，由下游自己的估算兜底。
