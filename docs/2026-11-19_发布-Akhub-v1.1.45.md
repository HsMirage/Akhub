### 2 的判据

终止信号（Chat `finish_reason` / Anthropic `stop_reason`、`message_stop` / Responses
`response.completed`、`response.incomplete`）已转发、且流里没有错误事件，下游此时断开 →
`Completed`：记录 `error_code` 为空、评分按成功计入。`response.failed` 与错误事件不置终止信号，
仍判失败；没有终止信号的中途断开仍记 `client_gone` 且不计证据。
现场 DeepSeek 官 key 分组 24 小时内 93% 的流式请求被误记为 `client_gone`，这是 sub2api / New API
读到终止事件就关连接的常态，不是掉线。
