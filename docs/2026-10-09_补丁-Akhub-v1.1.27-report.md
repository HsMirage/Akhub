# Akhub v1.1.27：xhigh 在不支持它的模型上折成 max

## 结论

1.1.27 已部署到生产 Akhub（89.58.17.138，容器 `akhub:1.1.27`），内外网验证通过、容器
`healthy`、重启次数 0，切换前后配置哈希与 1.1.26 完全一致（10 个分组 / 82 个上游账号 /
103 把 Key / 165 个逻辑模型 / 534 个调度目标）。

这是 1.1.26 的补丁：1.1.26 引入的自适应思考发射会把客户端要的 `xhigh` 原样发给上游，
而 4.6 家族只认 low/medium/high/max，于是换回一个 400。

## 触发与证据

发布 1.1.26 后的生产日志出现：

```
上游拒绝请求 account="supeai.cc-awsclaude" upstream_status=400
detail=This model does not support effort level 'xhigh'. Supported levels: high, low, max, medium.
```

对应请求记录（`request_records`）：`req_01M4G746RW2BEKTZA743TYVCPQ`，
`logical_model = claude-opus-4-6`、`upstream_model = claude-opus-4-6`、
`protocol = anthropic_messages`、`endpoint = messages`。

**这一条是既有行为，不是 1.1.26 引入的**：同协议透传按设计不改请求体（§14.1），
客户端自己发的 `output_config.effort = "xhigh"` 原样到了上游。但 1.1.26 新增的
**跨协议转换**路径同样可能发出 xhigh（例如 Responses 客户端 `reasoning.effort = "xhigh"`
转到 4.6 上游），那条路径是本次新引入的，必须自己收口。

## 修改内容

- `ThinkingContract` 增加 `xhigh` 事实：4.7 起才有这一档，4.6 家族（`claude-opus-4-6` /
  `claude-sonnet-4-6`）为 false，Kimi/Moonshot 与现代默认家族为 true。
- `align_thinking()` 发射 `output_config.effort` 前，若客户端要的是 `xhigh` 而目标模型
  不接受，则折成 `max`（该模型接受的最强档位），不再把上游不认识的取值发过去。
- 新增单测 `xhigh_is_folded_to_max_on_models_that_do_not_accept_it`：4.6 目标折成 `max`，
  5.x 目标保留 `xhigh`。
