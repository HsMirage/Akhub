## 调用路径与剩余风险

P-01，callflow：上游异常响应 → 解析等待头 → 健康状态结算 → 下一候选账号。目标是故障切换不断链；E-01、E-06 支撑 F-01。剩余风险：所有账号都故障时仍然正确返回失败；合法长等待时间仍遵从既有策略。

P-02，callflow：管理页读取评分 → 查统计表 → 缺失返回默认统计 → 不分配容量。目标是查询不改变评分历史；E-02、E-06 支撑 F-02。剩余风险：真实被采样目标超过原有 5000 上限时，既有淘汰策略仍存在。

P-03，callflow：旧查询发出 → 新配置保存成功 → 旧响应返回 → 拒绝版本倒退。E-03、E-06 支撑 F-03、F-04。剩余风险：服务重启与多个响应跨进程交错的极端场景，不具备服务端进程代际标识；本轮验证普通乱序与重启重置，不宣称分布式事务保证。

P-04，callflow：模型管理草稿 → 有流量确认框 → Esc/Tab → 只处理顶层 → 返回模型管理。E-04、E-06 支撑 F-05。P-05，callflow：手机断点 → 卡片说明与按钮分行 → 七页宽度检查及截图，E-05、E-06 支撑 F-06。

时间顺序：读取项目及保留原改动 → 经确认建立 CodeGraph → 既有测试基线 → 加入会失败的回归 → 修复 → 712 项回归及静态检查 → 正式构建浏览器验证 → 本机安装包制作。未使用子代理。
