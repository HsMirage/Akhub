## 发布中拦下的两个问题

两个都是**本地全绿、只有 CI 才能发现**的，记在这里是为了下次别再放过去。

### 1. 前端断言停在旧契约上（`npm test` 失败）

`web/src/lib/api.check.ts` 仍在断言"测试连接不带 `x-akhub-config-version`"——那是
v1.1.32 的行为。v26 重构把乐观锁从 `Admin` 提取器挪进了 `write_config` 事务：
写操作**必须**带这个头（`*` 表示无条件写入），"不带头部等于跳过检查"的旁路已删除。
断言随之改成"写操作一律携带"。

教训：契约改了要连带改断言，而 `cargo test` 不跑前端测试。

### 2. 一键升级用例依赖宿主环境（CI 全量测试失败）

`one_click_appears_when_an_update_is_available_and_supported` 只覆盖了部署形态
（`Deploy::Binary`），没覆盖"能否就地替换自己"，于是这条判断落到生产实现上——
读进程全局的 `AKHUB_ALLOW_RESTART`。

GitHub Actions 的 runner 自己就跑在 systemd 里，进程环境带着 `INVOCATION_ID`；
旧版 `can_self_replace` 认它，所以这条用例在 CI 上一直是绿的。`2bd414e` 按
"systemd 部署一键升级必然失败"删掉那条捷径后，CI 上就再也拿不到 true：

```
can_one_click=false  left: Bool(false)  right: true
```

本机（macOS）因为 `cli_updates_supported()` 为假直接跳过，看不到这个问题。
改用为这套场景准备的 `set_can_self_replace_for_tests` 显式给值，判断不再取决于宿主。

## v26 迁移：先演练，再上生产

迁移做四件事：重建 `upstream_accounts`（外键 CASCADE → SET NULL）、删凭据镜像列与
旧列、把手工目标补进目录、删零目标逻辑模型与两张旧表。整段在一个事务里，失败回滚、
库保持 v25 原样；`foreign_key_check` 不干净就回滚。

**上线前做了两层核对，没有直接上：**

1. **静态核账**（只读查询生产库）：`foreign_key_check` 干净、无孤立引用、
   重复账号名 0；三个会删数据的步骤在线上库上的影响都是 **0 行**
   （手工目标 0、重复目标 0、零目标逻辑模型 0）。
2. **真实迁移演练**（生产快照副本 + 1.1.42 镜像，独立容器、不发布端口）：
   3 秒内 `READY`，日志 `数据库结构已从 v25 升级到 v26`，`restarts=0`。

演练与生产迁移后的数据逐项对照，**完全一致**：

## 备份与回滚

备份目录：`/opt/akhub/release-1.1.42/backup/`

- `akhub.sqlite` — 发布前一致性快照（594,452,480 B，`integrity_check`=ok，
  `schema_version`=**25**，298,722 条请求记录）。用 Python `sqlite3.Connection.backup()`
  在 WAL 打开状态下取的，不是在跑的库文件直接 cp。
- `master.key` — 主密钥副本（600）
- `docker-compose.yml.before-1.1.42` — 发布前 compose（image 指向 1.1.41）
- `previous-image.txt` — 旧镜像 id `sha256:417cbd36…`

**回滚必须连数据库一起回**：v1.1.41 的二进制打不开 v26 的库，会明确拒绝启动
（"数据库结构版本 26 比当前二进制认识的 25 新"）。只换镜像回不去。

```bash
cd /opt/akhub
docker compose down akhub
cp -p release-1.1.42/backup/akhub.sqlite /var/lib/akhub/akhub.sqlite
rm -f /var/lib/akhub/akhub.sqlite-wal /var/lib/akhub/akhub.sqlite-shm
cp -p release-1.1.42/backup/docker-compose.yml.before-1.1.42 docker-compose.yml
docker compose up -d --no-deps akhub
curl -s http://127.0.0.1:8088/health/version
```

## 待观察

- **一键升级**：本版把 systemd 单元的运行布局改成与容器一致（`ExecStartPre` 复制到
  `/var/lib/akhub/runtime/akhub`），并让 `can_self_replace` 只认 `AKHUB_ALLOW_RESTART`。
  容器部署由入口脚本设这个变量，所以面板上的"一键升级"入口本版起对容器也应可用——
  下次发版可以顺手验一下，别只在 systemd 上验过。
- 删掉了 `/admin/api/metrics`、逐行模型写接口与 `performance_buckets` 表。面板已不再调用，
  但**外部脚本若还在打这些接口会 404**。
- `performance_buckets`（96,969 行）随迁移删除；性能统计改由 `target_perf_snapshot` 承载。
- 乐观锁头部现在是**必填**：直接用 `curl` 手调管理写接口的脚本要补上
  `x-akhub-config-version: *`（或具体修订号），否则回 400。
