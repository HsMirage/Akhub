### Linux 编译机 10.1.1.10

```
785 项测试通过、0 失败（cargo test --release --locked）
二进制 /opt/builds/akhub/20261005-claude-forwarding/target/release/akhub
  SHA-256 cf96793103fb4340df269a8bb85db020a7ef5cda9ba2c3af093cf54fce0cef04
  24,402,928 字节
```

**首次构建踩到的坑（值得记一笔）**：直接跑 `cargo build` 时 `web/dist` 不存在，
`build.rs` 会写入一个"管理后台尚未构建"的占位页并只给一条 warning——而这一版
**恰好改了前端**（账号表单的无状态预览）。若按老脚本一路跑下去，发出去的镜像会带
占位页，管理后台整个不可用，而网关接口看起来一切正常。

处理：先在编译机上 `npm ci && npm run build` 生成真实 `web/dist`，再编 Rust。
验证方式是新版前端资源的哈希：编译机产物 `index-QOtCFAaa.js` 与线上
`/admin` 返回的引用**完全一致**，占位页不会产生这个文件。

## 回滚

```bash
# 只有本版容器会回滚；数据库不动。
bash /opt/akhub/release-1.1.29/rollback.sh
```

脚本先校验当前镜像确实是 `1.1.29`，再恢复
`release-1.1.29/backup/docker-compose.yml`（指向 1.1.28）并 recreate。
旧镜像 `ghcr.io/hsmirage/akhub:1.1.28` 保留在本机。

本次没有数据库结构变更，**不应恢复数据库快照**覆盖发布后的请求记录。

可用档位重发"。
