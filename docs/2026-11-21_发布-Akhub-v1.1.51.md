# 发布 Akhub v1.1.51：上游 cyber_policy 拒绝保留错误码，下游按量计费

## 现场

2026-11-21 22:40–22:47，gpt-6.2-sol / gpt-5.6-sol 经账号「吱吱鼠-教学GPT」，连续多条：

| 位置 | 记录 |
|---|---|
| 上游吱吱鼠 | `流状态: 错误 eof`，按输入 token 扣费 |
| Akhub | `error_code=upstream_protocol_error`，输入 9174（估算），输出空 |
| sub2api | 输入 0 / 输出 0 / 费用 0，日志 `openai_usage.non_billable_upstream_request_error` |

上游原文：`Request blocked by cyber policy.` / `This content was flagged for possible cybersecurity risk...`。
上游扣了钱、下游没收钱，差价落在我们身上。

## 根因

1. Akhub 脱敏上游错误帧时，把错误码统一改写成 `upstream_protocol_error`（`src/gateway/error.rs`）。
2. sub2api 只认 `error.code == "cyber_policy"`（`openai_cyber_policy.go:80`）才走 cyber 路径、
   按上游报告的 token 计费；其余流内错误一律标 `NonBillableUpstreamError`，费用清零
   （`openai_gateway_usage.go:351`）。
3. 另外，Responses 的 `response.failed` 错误在 `response.error` 里，`frame_error` 认不出来，
   v1.1.48 的「错误帧之前先补用量帧」在这种形状上不生效。

## 改法

- `private_error_frame`：上游错误码是 `cyber_policy` 时原样保留（这是 OpenAI 公开错误码，
  不含渠道信息）；消息与其余字段照旧脱敏，别的错误码照旧改写。
- `settle.rs` 新增 `is_error_frame`：`response.failed` 也算错误帧，用量帧补在它之前。

## 下游影响

- sub2api 对 cyber 拒绝改为按上游 token 计费，用量行 `request_type=4`（cyber）。
- sub2api 的 cyber 会话屏蔽（`cyber_session_block_enabled=false`）与风控（`risk_control_enabled=false`）
  当前都是关的，所以**不封会话、不发邮件、不影响用户继续使用**。以后若打开这两个开关，cyber 命中会触发它们。
- content policy 类拒绝（非 cyber_policy）不变，仍按 sub2api 规则免费。

## 测试

- 单元：`cyber_policy_code_survives_redaction`（Responses failed / 裸 error × 三协议，且别的码仍被改写）。
- 集成：`a_responses_cyber_failure_keeps_its_code_and_bills_usage_first`。
- 编译机全量通过（540 单元 + 全部集成目标），clippy `-D warnings` 与 `fmt --check` 干净。
