# v1.1.49 发版记录

基线 v1.1.48。**没有结构变更**，启动不迁移数据。本次只改两处**可观测性**，
网关转发的请求体与响应体一个字节都没动。

## 起因

用户看到记录页上刚发出的请求标着红色的「降级 thinking」，以为思考档位被压低了。
查库（`req_01M7X7TDF3RDB8XPQEDMKBEE0P`，2026-11-21 03:44:32）确认：

- `degraded=thinking`、`http_status=200`、`attempts=1`、`effort_retries=0`；
- 上游 `upstream_status=200`，`reasoning_tokens` 有值；
- 该分组 48 小时内 `chat_completions` 入口 1355 条**零降级**，`responses` 入口
  140 条里 128 条降级——只有 Responses 的历史里带 reasoning 项。

两件事撞在同一个词上：**历史思考块被摘掉**（不可重放，必须丢）与**思考档位被
折/被换**（真降档）都记成 `thinking`，读起来就像档位被砍了。

## 发版内容

| # | 修复 | 落点 |
|---|---|---|
| 1 | 摘除不可重放的历史思考块改记 `thinking_history`，与 `effort` 区分开 | `src/gateway/passthrough.rs`、`src/protocol/degrade.rs` |
| 2 | 「发出的档位」读回 `reasoning.effort` / `reasoning_effort`，不再只有 Anthropic 的 `output_config.effort` 看得见 | `src/gateway/passthrough.rs` |

### 1. 改名（只改标记，不改行为）

`strip_foreign_replay_state()` 摘掉的是**请求历史里**没有 `encrypted_content`
的 reasoning 项 / 没有签名的 thinking 块——离开原上游就不可重放，留着只会被
上游 400。摘除逻辑一行没动，只把记下的能力名从 `thinking` 换成
`thinking_history`。

跨协议真丢思考（例如 Messages → Chat 丢弃思考块）仍记 `thinking`：那才是
「这次回答没有思考过程」。档位被折（Anthropic 的 `max` 折到 OpenAI 的
`xhigh`）仍记 `effort`。三个标记语义各自独立。

### 2. 「发出的档位」为什么大多是「默认」

`body_effort()` 原先只认 Anthropic 的 `output_config.effort`。同一协议透传时
OpenAI 家族把档位放在 `reasoning.effort`（Responses）或 `reasoning_effort`
（Chat），于是一直读回 `None`，记录页显示「默认」——档位明明发出去了，人却
看不见。现在三条路径都认。

`sent_effort`（喂"这一档在这个账号上可用"的证据）保持只认 Anthropic 形状：
那条证据链服务的是自适应契约的档位升降，不该被另两个协议的字段带偏。
