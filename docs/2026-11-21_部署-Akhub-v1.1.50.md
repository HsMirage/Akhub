## 重要边界：sub2api 会取消上游请求

这次上线的是「客户端断开后继续读完上游」，但线上拓扑里断开的**发起方是
sub2api**：它检测到终端客户端掉线后，会 `context canceled` 掉发往 Akhub 的请求。
Akhub 收到的就是取消信号，上游连接随之关闭——drain 没有字节可读。

现场证据（`req_01M7YD89` 那次的 sub2api 日志）：

```
openai.client_disconnected ... "error": "stream usage incomplete after disconnect: context canceled"
```

所以：

- **能修好的**：断开前已经到达 Akhub 的用量，现在一定会被记下来（v1.1.48 起）。
- **这次补上的**：上游先断（EOF / 错误事件）时，计费终止帧照旧补发。
- **修不了的**：sub2api 主动取消时，断开之后的用量 Akhub 拿不到——它连连接都
  没了。要拿到只有两条路，都不在 Akhub 这侧：
  1. sub2api 取消时改成「继续读完上游再定价」（它日志里已经有
     `continuing to drain upstream for billing` 的意图，但对 responses 流没做到）；
  2. 让 sub2api 不在客户端断开时取消上游请求。
